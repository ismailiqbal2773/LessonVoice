# Internal API contract

Project JSON: `{version:1,title:string,language:"en"|"ur",rate:150,voice:"warm-female",sections:[{id:string,title:string,text:string}],pronunciations:[{term:string,say:string}],questions:[{question:string,answer:string}]}`. Voice preset IDs: `warm-female`, `clear-male`, `storyteller-female`, `calm-male`. Missing `voice` in an older draft defaults to `warm-female`; unsupported or empty IDs are rejected. Limits: title 120, lesson 20,000 characters total, max 24 sections, max 1,500 characters/section; 30 rules and 30 questions. Rate 100–220 relative units (150 is 1×). Native script Urdu is supported subject to installed offline model feasibility; transliteration is not translation.

- `GET /api/health` -> `{ok:true,engine:{name,available,languages:["en","ur"],message}}`
- `POST /api/segment` `{text}` -> `{sections:[{id,title,text}]}`; separate paragraphs and bound chunks.
- `POST /api/spoken` `{project}` -> `{sections:[{id,text}]}` preview after pronunciation replacement.
- `POST /api/audio` `{project,sectionId}` -> WAV bytes with Content-Type audio/wav; errors JSON `{error}`. Generate one section at a time, offline neural engine by default, or explicit paid mode as documented below; no automatic provider fallback. Frontend caches each result in memory with its spoken-text/language/rate/voice signature; relevant changes invalidate it. Missing model/runtime returns a clear unavailable-engine error.
- `POST /api/voice-preview` `{language,rate,voice}` -> WAV bytes with Content-Type audio/wav, using a short fixed sample in the selected language and the same offline speech engine/settings as section generation. It shares the generation concurrency lock and clear 400/503 error handling. No lesson or project is required. Changing the selected voice must invalidate cached lesson audio.
- `POST /api/export` `{project,audio:[{id,data:base64,signature:string}]}` -> application/zip. Server independently recomputes signature from actual spoken content/settings and rejects missing/stale/invalid audio. Response filename `lessonvoice-pack.zip`. Pack contains manifest.json, original-transcript.txt, spoken-transcript.txt, questions.txt, answer-key.txt, index.html, audio/section-NN.wav. User explicitly exports answer key together with learning pack (UI reminder).

Errors 400 validation, 403 host/origin, 404 route, 413 size, 415 media type, 503 unavailable voice engine, 500 processing failure. API is stateless: app draft saved only in browser localStorage; audio in tab memory. Export and audio requests temporarily process data in the Python process.

Signature shared algorithm: SHA-256 of UTF-8 `JSON.stringify([language,rate,voice,spokenText])` with no spaces, Unicode preserved, hexadecimal lowercase. Backend Python json.dumps(...,ensure_ascii=False,separators=(',',':')). Missing voice is canonicalized to `warm-female` before signing. Older three-element audio signatures are stale and rejected; original draft text remains importable. Exported manifest records the selected voice. Audio validation accepts only mono, 16-bit PCM WAV at 22,050 or 24,000 Hz, nontruncated/nonconstant and at least 0.05 seconds but no more than five minutes per section; limits are 10 MB per audio and 96 MB total audio per pack.


## 30 October 2026 speech update

Offline remains the default. Local OmniVoice now uses 64 synthesis steps. Audio/voice-preview requests may include a separate `speech` object: `{provider:"elevenlabs", apiKey:"...", voiceId:"...", consent:true}`. This explicitly sends spoken text to the fixed ElevenLabs HTTPS endpoint using eleven_v3 and pcm_24000. Credentials are request-scoped, excluded from project/draft/export metadata and never logged. Missing/invalid settings are rejected; no automatic cloud fallback exists. Previous offline review statements apply to offline mode only. Paid synthesis still requires account credits and live validation with a funded key. See README.

Exports optionally accept `speechSource:{provider:"local"|"elevenlabs",voiceId:string}` and record only an allowlisted public provenance summary. It never includes API keys. Text signatures still bind project settings, not provider identity; the UI discards audio on provider/credential changes.
